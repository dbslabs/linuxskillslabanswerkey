CompTIA A+ Core 2: Linux Skills Lab

Instructor Answer Key

In every sample, student stands for the student's own user name. Output will vary by server, Ubuntu release, date, and file sizes, so grade on whether the output shows the correct command was run, not on exact matches[cite: 17].

Instructor Notes

  • Check before class that vim is installed. Minimal Ubuntu servers often include only vi (vim-tiny). Every vim step in Exercise 4 works in vim-tiny except extra features, but the full package is better[cite: 17].
  • pico may not exist on your server. If students report "command not found", accept that as evidence and have them use nano[cite: 17].
  • man pages are missing on some minimal installs. If man fsck fails, accept an answer based on fsck -h or a web lookup[cite: 17].
  • Exercise 9 needs the e2fsprogs package (installed by default). If mkfs.ext4 is not found, try /sbin/mkfs.ext4. The image file uses 10 MB, so check any disk quotas[cite: 17].
  • To detect copied work, look for each student's own user name in paths such as /home/student/lab and in the prompt[cite: 17].
  • Suggested scoring: 10 points per exercise, 100 total. Give about 6 points for correct commands and output, and about 4 points for the written explanation[cite: 17].

Exercise 1 Answer Key: Navigation Basics

Expected Results

  • pwd shows /home/student[cite: 17].
  • ls -la ~/lab lists ., .., backup, docs, and logs. Directories show a leading d in the permissions[cite: 17].
  • ls -la shows hidden files (names starting with a dot), permissions, owner, group, size, and date. ls -l shows the long format but hides dot files[cite: 17].

Exercise 2 Answer Key: nano

Expected Results

  • The cat output shows six lines: the name, the date, three commands, and the added sixth line[cite: 17].
  • Save and exit keystrokes: Ctrl+O, Enter to confirm the file name, then Ctrl+X[cite: 17].
  • Accept students who describe the nano footer prompts (for example "^O Write Out" and "^X Exit") in their own words[cite: 17].

Exercise 3 Answer Key: pico and vi

Expected Results

  • pico_test.txt contains two lines. vi_test.txt contains three lines about why they are taking A+[cite: 17].
  • :wq writes (saves) and quits[cite: 17].
  • :q quits, but vi refuses if there are unsaved changes[cite: 17].
  • :q! quits and discards unsaved changes[cite: 17].
  • The :q! step should not alter the file, so the cat output must still show the three saved lines[cite: 17].

Exercise 4 Answer Key: vim

Expected Results

  • Students' final text varies because they choose which line to delete or copy. The required evidence is that banana no longer appears and mango does[cite: 17].
  • Expected command list with descriptions: i enters insert mode; Esc returns to normal mode; dd deletes the current line; yy copies (yanks) the current line; p pastes below the cursor; u undoes the last change; /banana searches forward (n goes to the next match); :%s/banana/mango/g replaces every match in the file; :wq saves and quits[cite: 17].
  • Example result: the cursor starts on the last line, so dd removes the second banana, yy and p duplicate cherry, and u undoes the paste[cite: 17].

Sample Output

Sample final cat output (one possible result)[cite: 17]:

apple
mango
cherry

Exercise 6 Answer Key: Moving, Renaming, and Deleting

Expected Results

  • The "before" listing matches the Exercise 5 sample. In the "after" listing, docs holds notes.txt, os_details.txt, and vim_test.txt; logs holds pico_test.txt; and backup is unchanged[cite: 17].
  • rm -i prompts like "rm: remove regular file '/home/student/lab/docs/notes_copy.txt'?" and the file is deleted after y[cite: 17].
  • rmdir works only on empty directories. rm -r removes a directory and its contents[cite: 17].
  • Model answer for rm -rf: it recursively deletes everything without asking, ignores errors, and has no recycle bin, so a typo or wrong path (for example a stray space or a wrong variable) can permanently destroy important data. There is no undo[cite: 17].

Exercise 7 Answer Key: find and grep

Expected Results

  • find ~/lab -name "*.txt" lists every text file under the lab, including those in backup[cite: 17].
  • 2>/dev/null discards permission-denied errors. head -20 shows only the first 20 lines[cite: 17].
  • grep "Ubuntu" prints only lines containing that exact capitalization, such as the NAME and PRETTY_NAME lines[cite: 17].
  • -i ignores case, so lines with "ubuntu" in lower case also match (for example ID=ubuntu)[cite: 17].
  • -n shows the line number before each match[cite: 17].
  • -r searches recursively through a directory. grep -r "mango" ~/lab should show two matches: docs/vim_test.txt and backup/docs/vim_test.txt[cite: 17].
  • -v inverts the match and shows lines that do not contain the pattern. Most Ubuntu os-release files have no # characters, so the whole file usually prints. That is correct[cite: 17].

Exercise 8 Answer Key: df and du

Expected Results

  • The home directory is usually on the filesystem mounted at / (for example /dev/sda1 or /dev/mapper/ubuntu--vg-ubuntu--lv). Accept another mount point if the server has a separate /home[cite: 17].
  • du -sh ~/lab is small, typically a few dozen KB (for example 60K). Used space on / is much larger, usually gigabytes[cite: 17].
  • -h means human-readable: sizes appear as K, M, and G instead of raw blocks[cite: 17].
  • df -i shows inode usage (the count of files and directories), not byte usage[cite: 17].

Exercise 9 Answer Key: fsck

Expected Results

  • Expected output shows the five passes, ending with a summary line. Version and numbers vary[cite: 17].
  • -y answers yes to every repair prompt automatically. -n opens the filesystem read-only and answers no to every prompt, so nothing is changed[cite: 17].
  • practice.img does not appear in df -h because it is a regular file that was never mounted[cite: 17].
  • Model answer (why not mounted): a mounted filesystem is being changed while it is checked, and the kernel's cached data may not match the disk. fsck could "repair" good data and corrupt the filesystem[cite: 17].
  • Model answer (when to run it): after a crash or power loss, disk errors, or boot failures. Unmount the filesystem first (or boot recovery mode or live media), then run it as root, for example sudo fsck /dev/sdXN[cite: 17].

Exercise 10 Answer Key: Pipes and Escaping

Expected Results

  • Part A: Counts and sizes vary. Each command should show output, and the final cat shows lines from df -h that contain /dev[cite: 17].
  • touch ~/lab/my\ file.txt succeeds because the backslash escapes the space, so it becomes part of the file name instead of a separator[cite: 17].
  • touch "~/lab/my other file.txt" fails with "No such file or directory". Inside quotes the shell does not expand ~, so it looks for a directory literally named ~. Correct versions: touch "$HOME/lab/my other file.txt" or touch ~/lab/"my other file.txt"[cite: 17].
  • echo "Hello $NAME" prints Hello Student because double quotes allow variable expansion[cite: 17].
  • echo 'Hello $NAME' prints Hello $NAME because single quotes keep every character literal[cite: 17].
  • echo "Cost is \$5" prints Cost is $5. echo "She said \"hello\"" prints She said "hello"[cite: 17].
  • find ~/lab -name "my*" | grep "file" prints /home/student/lab/my file.txt. The second file was not created, which is the expected result[cite: 17].
  • Model answer: single quotes treat everything literally; double quotes group text but still expand variables, $, backslash, and command substitution; a backslash escapes only the single character that follows it[cite: 17].
